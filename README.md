# Atman LLM Evolution Lab

[English](README_en.md)

> 按人工智能技术演进顺序，分阶段构建不同时代的大语言模型体系。

## 1. 项目定位

本项目不是同一模型的连续升级工程，也不是让 v1、v2、v3 在同一排行榜上竞争。

v1、v2、v3 分别对应不同发展阶段的独立产物。每个版本都有自己的模型架构、数据流程、训练方法、能力目标和评测方式。一个版本完成后，将保留其时代特征、实验结果与能力边界，再进入下一个版本。

未来如果出现新的、相对稳定的 AI 技术范式，本项目可以继续增加 v4、v5，而不需要回头改造已经完成的历史版本。

## 2. 版本路线

| 项目版本 | 对应阶段 | 核心版本目标 | 状态 |
|---|---|---|---|
| **v1** | 基础语言模型与规模化预训练阶段 | 从零完成 Tokenizer、Decoder-only Transformer、预训练、生成和基础评测 | 目录与设计阶段 |
| **v2** | 指令对齐与现代开源模型阶段 | 实现现代模型架构、SFT、多轮对话、偏好对齐和基础工具调用 | 规划中 |
| **v3** | 推理与 Agent 阶段 | 实现 Thinking、Reasoning RL、推理预算、工具使用和 Agent 训练 | 规划中 |
| **v4+** | 未来阶段 | 在新的技术范式形成后再定义 | 保留 |

这里的 v1/v2/v3 是本项目内部的架构版本，不等同于任何厂商模型的版本号。

## 3. 各版本关系

```text
v1：完成基础语言模型的完整闭环
 ↓ 完成、记录并保留
v2：重新设计面向指令对齐与对话的完整体系
 ↓ 完成、记录并保留
v3：重新设计面向推理与 Agent 的完整体系
 ↓
v4：等待下一代稳定范式出现后定义
```

版本之间遵循以下原则：

1. **阶段独立**：每个版本可以独立理解、训练、评测和运行。
2. **保留时代特征**：不为了兼容后续版本，把未来技术提前塞进早期版本。
3. **不强制向后兼容**：后续版本可以更换 Tokenizer、架构、数据、训练目标和接口。
4. **不做不对等排名**：不同版本不使用一个综合分数判断优劣。
5. **版本内进行实验**：只在同一版本内部比较 small、medium、large 或受控实验变量。
6. **完成后封存**：记录配置、数据来源、训练结果、失败实验和能力边界。

## 4. 阶段说明

### 4.1 v1：基础语言模型

v1 面向基础语言模型，构建从原始语料到可生成文本模型的完整工程链路。

主要内容：

- 原始语料下载、清洗和切分
- Tokenizer 训练与验证
- Decoder-only Transformer
- Causal Language Modeling
- 模型预训练与断点恢复
- Loss、Perplexity 和文本生成评测
- 基础 zero-shot / few-shot / ICL 能力验证
- small、medium、large 三种规模实验

v1 不以稳定指令遵循、Thinking、RLHF、DPO 或 Agent 为目标。

详细说明见 [`v1/README.md`](v1/README.md)。

### 4.2 v2：指令对齐与现代开源模型

v2 对应预训练模型向实用对话助手发展的阶段，计划关注：

- RoPE、RMSNorm、SwiGLU、GQA 等现代架构
- Chat Template 与多轮对话
- Supervised Fine-Tuning（SFT）
- 偏好数据与 DPO/RLHF
- 指令遵循、格式控制与安全对齐
- 基础 Function Calling / Tool Calling

v2 将作为独立版本设计，不要求继承 v1 的权重、Tokenizer 或代码实现。

### 4.3 v3：推理与 Agent

v3 对应推理模型与 Agent 发展的阶段，计划关注：

- Thinking / Non-Thinking 双模式
- 长链推理数据与冷启动 SFT
- 可验证奖励与 Reasoning RL
- 推理预算和测试时计算
- 多轮工具调用、规划和错误恢复
- Agent 环境与任务奖励

MoE、MLA、超长上下文等可以作为这一阶段的专题实验，但不自动成为 v3 的必选条件。

### 4.4 v4 及后续版本

v4 暂不预设能力清单。只有当新的技术路线形成相对明确、稳定的范式后，才确定其目标和边界，避免仅根据年份或营销名称划分版本。

## 5. 项目目录

```text
new/
├── README.md
├── README_en.md
├── v1/                     # 当前阶段：基础语言模型
├── v2/                     # 后续阶段：指令对齐与对话
└── v3/                     # 后续阶段：推理与 Agent
```

每个版本的内部目录、依赖和实验记录由该版本自己维护，不建立强制共享的模型实现或统一排行榜。

## 6. 评测原则

各版本按照自身目标验收：

| 版本 | 主要验证内容 |
|---|---|
| v1 | 预训练收敛、Loss/PPL、语言生成、基础 ICL、规模变化 |
| v2 | 指令遵循、多轮对话、知识问答、格式控制、偏好对齐 |
| v3 | 可验证推理、Thinking 控制、工具调用、任务规划、Agent 完成率 |

不同版本回答同一道题时，只能用于展示技术演进，不能视为控制变量严格一致的公平比较。

## 7. 当前工作范围

当前只推进 **v1**：

1. 明确目录与文档；
2. 确定 v1 架构设计；
3. 确定 small、medium、large 配置；
4. 确定数据和 Tokenizer 方案；
5. 再进入代码实现和实验。

v2、v3 暂时只保留阶段定义，不提前实现。

## 8. 说明

- 时间范围用于帮助理解技术演进，不是严格的学术分期。
- 同一年可能同时存在多种模型范式，个别模型也可能跨越阶段边界。
- 本项目的重点是完整呈现各技术阶段的架构、训练体系、能力范围与工程边界。
- 文档中提到的 Thinking 不等于结果必然正确；推理结果仍需要验证和工具支持。
