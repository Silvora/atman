# v1-dense 设计文档

## 1. 设计边界

本版本只研究 Dense Decoder-only 模型的现代化结构和长上下文能力。数据源、清洗和 Tokenizer 沿用 `v1-base`，模型代码、序列长度、训练配置和实验产物独立管理。

与 `v1-base` 不同，本分支的 Tokenizer 配置预留了对话角色、Thinking、工具调用和扩展 token。词表重新生成后，所有编码数据必须重新生成。

## 2. 模型结构

### 2.1 RoPE

删除学习型绝对位置嵌入，在 Query 和 Key 上应用旋转位置编码。基础上下文先设置为 32,768；扩展到 131,072 时使用经过验证的 RoPE scaling 配置，并对短文本和长文本分别评测。

### 2.2 RMSNorm

使用 RMSNorm 替代 LayerNorm，保留 Pre-Norm 残差结构。归一化位置和 epsilon 必须写入模型配置，不能在代码中隐式决定。

### 2.3 SwiGLU

前馈层使用门控结构：

```text
SwiGLU(x) = W_down( SiLU(W_gate(x)) ⊙ W_up(x) )
```

`ffn_dim` 需要按参数预算重新计算，不能直接沿用 GELU MLP 的中间维度。

### 2.4 GQA

Query 头数量大于 Key/Value 头数量。配置必须同时记录 `n_heads` 和 `n_kv_heads`，并检查 `n_heads % n_kv_heads == 0`。训练阶段使用标准因果注意力，推理阶段使用 KV Cache 验证显存收益。

### 2.5 长上下文

| 阶段 | sequence length | 用途 |
|---|---:|---|
| 结构验收 | 2,048 | 与 v1-base 对齐、快速排查实现错误 |
| 第一阶段 | 32,768 | 长上下文正式训练和验证 |
| 扩展阶段 | 131,072 | 长文档和跨段落能力实验 |

复制来的 `data/encoded/*.bin` 每条记录是 2,048 输入长度，不能直接用于 32K/128K 训练。编码脚本需要增加上下文长度参数，并为每个长度保存独立的报告和文件目录。

## 3. 建议配置基线

small、medium、large 保持三个配置名不变。结构参数在代码实现前以表格方式冻结，并记录实际参数量：

| 配置 | d_model | 层数 | Query heads | KV heads | 第一阶段上下文 |
|---|---:|---:|---:|---:|---:|
| small | 512 | 8 | 8 | 2 | 32K |
| medium | 768 | 12 | 12 | 4 | 32K |
| large | 1024 | 24 | 16 | 4 | 32K |

这些数值是 Dense 分支的开发基线，正式训练前必须由模型实现重新统计参数量和显存需求。

## 4. 验证项目

- RoPE 在不同位置的旋转结果和缓存结果一致；
- GQA 的 Query/KV 头形状满足整除约束；
- KV Cache 生成与完整前向生成逐 token 一致；
- SwiGLU 和 RMSNorm 的前向、反向无 NaN；
- 2K、32K、128K 输入的 loss、显存和吞吐分别记录；
- 训练和验证文件的 tokenizer、词表和 EOS 版本一致。

## 5. 不纳入本版本的内容

本版本不引入 MoE、MLA、视觉编码器和推理强化学习。这些内容属于 `v1-moe` 或后续训练阶段。
